# Building ZisK 1.2.0-alpha for a 12 GB RTX 4080

Stock 1.2.0 refuses to prove on an RTX 4080 Laptop (12,282 MiB):

    Max prover buffer size: 12.81 GB
    Error: Invalid configuration: Not enough GPU memory to run the proof

Two changes make aggregated GPU proving work. Both are needed; neither is
sufficient alone.

## 1. PIL air sizes (this repo)

`pil/zisk.pil`: eleven airs 2**22 -> 2**21, Keccakf 2**18 -> 2**16. Takes the
basic prover buffer from 12.81 GB to 5.27 GB and the largest air to 3.25 GB.

`pil/src/pil_helpers/traces.rs` is generated and must be regenerated to match --
air sizes are compiled into the binary as well as declared in the PIL, and a
mismatch is a hard failure.

Do NOT reach for `lanes_per_row` (must divide 25) without also updating
`precompiles/keccakf/src/keccakf_constants.rs::LANES_PER_ROW` and enabling the
`set_all_chi_acc` write that upstream leaves commented out for wide layouts.
The build catches the mismatch at compile time, loudly.

Note that shrinking N does NOT shrink an air's compressor: the compressor
scales with trace *width*. Keccakf's compressor is 2^20 x 107 = 3.34 GB at
N=2**18, 2**17 and 2**16 alike.

## 2. GPU memory reserve (pil2-proofman)

`common/src/proof_ctx.rs::GPU_MEMORY_RESERVE_MB` 1536 -> 256, on branch
`rtx4080-12gb-fit-1.2.0` of the proofman fork. Wired in via `[patch.crates-io]`
in this repo's `Cargo.toml`, which expects the proofman checkout as a sibling
directory (`../pil2-proofman`).

The reserve is what actually decides it:

    reserve 1536 MB -> aux budget 5.54 GB, required 6.68 GB -> refused
    reserve  256 MB -> aux budget 6.79 GB, required 6.68 GB -> works

Headroom is ~110 MB. Anything else holding VRAM (an LLM runtime with a model
resident, GPU video decode) puts it back over the line.

## Build

NodeJS >= 20. `CUDA_ARCHS=89` for Ada.

    # 1. fixed data
    cargo run --release --bin zisk-arith-frops-fixed-gen
    cargo run --release --bin zisk-binary-basic-frops-fixed-gen
    cargo run --release --bin zisk-binary-extension-frops-fixed-gen

    # 2. compile-pil  (output MUST be named zisk.pilout)
    cargo-zisk-dev proofman-setup compile-pil --pil pil/zisk.pil \
      --include "pil,../pil2-proofman/pil2-components/lib/std/pil,state-machines,precompiles" \
      --output pil/zisk.pilout --fixed-dir tmp/fixed --fixed-to-file --no-proto-fixed-data

    # 3. pil-helpers -> regenerates pil/src/pil_helpers/traces.rs
    cargo run --release --manifest-path ../pil2-proofman/Cargo.toml -p proofman-cli -- \
      pil-helpers --pilout pil/zisk.pilout --path pil/src -o

    # 4. tools
    CUDA_ARCHS=89 cargo build --release

    # 5. proving key
    cargo-zisk-dev proofman-setup setup --airout pil/zisk.pilout \
      --build-dir <BUILD_HOME> --fixed-dir tmp/fixed \
      --stark-structs state-machines/starkstructs.json --recursive --gen-exps --exps-arch 89

    # 6. constant trees -- ziskup does this post-install; from source you must
    #    run it yourself or the key is incomplete (no .consttree/.const_gpu files)
    cargo-zisk-dev check-setup --proving-key <BUILD_HOME>/provingKey -a --gpu

### Undocumented environment for step 5

circom is not a system dependency; it ships inside proofman. Step 5 fails with
`Failed to execute circom compiler: No such file or directory` without:

    export PATH="$PM/setup/circom:$PATH"
    export CIRCOM_HELPERS_DIR="$PM/setup/circom"
    export CIRCUITS_GL_PATH="$PM/setup/stark-recurser/stark2circom/circom_verifier/circuits.gl"
    export RECURSER_CIRCUITS_PATH="$PM/setup/stark-recurser/stark2circom/circom_verifier/helper_circuits"
    export RECURSER_CIRCUITS_COMPRESSED_FINAL_PATH="$PM/setup/stark-recurser/stark2circom/circom_verifier/helper_circuits"
    export STD_PIL_PATH="$PM/pil2-components/lib/std/pil"
    export RECURSER_PIL_PATH="$PM/setup/stark-recurser/plonk2pil/pil"
    export GOLDILOCKS_SRC_DIR="$PM/pil2-stark/src/goldilocks/src"
    export FINAL_SNARK_CIRCOM_HELPERS_DIR="$PM/setup/final_snark_circom"

Long builds should run outside `app.slice` with a memory cap; an unguarded run
hard-hung this machine, and a too-small MemorySwapMax silently stalls setup for
hours instead of failing.

## Results (RTX 4080 Laptop, aggregated + verified)

| workload           | steps   | 1.2.0 patched | 1.1.0 patched |
|--------------------|---------|---------------|---------------|
| fibonacci          | 2,485   | 15.00 s       | 11.45 s       |
| sha-hasher n=1000  | 2.44 M  | 13.33 s       | 12.24 s       |
| sha-hasher n=10000 | 24.0 M  | 20.57 s       | 28.25 s       |
| sha-hasher n=1e5   | 239.7 M | 135.91 s      | 199.83 s      |

Security parameters are identical to stock: blowup 2x, nQueries 228/217,
GL hash, merkle arity 4, JBR regime, proximityGap 0.00333. Only table capacity
changed.

Proofs verify only against a verifier built from THIS key, not ZisK's official
one. Fine for local dev; on-chain use needs a regenerated verifier contract or
a >= 24 GB card.
